# Изменения архитектуры

- [x] Тонкие HTTP-контроллеры: параметры, доступ, вызов сценария и ответ.
- [x] Отдельные Orders::Create, Complete, Cancel; формат JSON проверяется ActiveModel-формой.
- [x] Тонкие модели: связи, scopes, поля и небольшие защитные валидации.
- [x] JSON-представления вынесены в Jbuilder, пагинация делегирована Kaminari.
- [x] Проведение и финансовые правила перенесены в Ledger::Post и Ledger::Validation.
- [x] Добавлена миграция удаления всех пользовательских триггеров и функций.
- [x] Схема переключена на schema.rb; исторические миграции сохранены.
- [x] Демоданные перенесены из app/services в db/seeds.
- [x] Проверки финансовых правил перенесены с SQL-триггеров на сервисную границу.
- [x] Документация описывает новые границы гарантий и порядок блокировок.
- [x] Namespace контроллеров развёрнуты; общий BaseService передаёт аргументы через `...`.
- [x] Добавлены frozen string literals и соответствующие правила RuboCop.
- [x] Удалены неиспользуемые Rails-компоненты и зависимости обработки изображений/Thruster.
- [x] Общие RSpec-помощники вынесены в spec/support; чистые Ruby-тесты отделены от Rails.
- [x] Финансовые поля получили комментарии в схеме через новую миграцию.
- [x] Dockerfile упрощён; CI дополнен проверкой обновления существующей базы.

HTTP-контракт и поведение frontend сохраняются. Удаление триггеров меняет гарантию:
прямые записи SQL больше не проверяют финансовую согласованность.
Рабочие сценарии должны проходить через сервисы.

## Проверки

На локальном Ruby 3.4.10, Rails 8.1.3.1 и PostgreSQL 17.6 проверены RSpec,
Zeitwerk, создание новой базы и обновление исторической схемы с проведёнными
операциями. На момент переработки RSpec содержит 110 примеров.
Frontend: 19 тестов, TypeScript, ESLint и production-сборка прошли.
RuboCop и Brakeman запущены отдельно на portable Ruby 4; аудит Gemfile.lock
не обнаружил известных уязвимостей в используемой базе advisories.

Проверки выполнены без Docker: локальный Docker Desktop неисправен.
Сборку изменённого Dockerfile и полный GitHub Actions workflow нужно проверить
в рабочем Docker-окружении. CI-конфигурация включает все проверки выше.
